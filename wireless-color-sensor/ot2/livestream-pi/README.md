# OT-2 livestream Pi: files installed on it

The OT-2 livestream runs on a Pi Zero 2 W (`OT2_STREAM_CAM_HOSTNAME`), set up in
[#172](https://github.com/vertical-cloud-lab/byu-vcl/issues/172#issuecomment-5139754959).
This directory keeps copies of files put on it since then, so that a rebuilt Pi
can be given them again.

| file here | on the Pi | installed | what it does |
| --- | --- | --- | --- |
| [`no-ipv4-acd.conf`](no-ipv4-acd.conf) | `/etc/NetworkManager/conf.d/no-ipv4-acd.conf` | 2026-09-26 03:44 MDT, [#237](https://github.com/vertical-cloud-lab/byu-vcl/issues/237) | turns off NetworkManager's IPv4 address conflict detection (ACD), which was dropping the Pi's address |

The stream watchdog, `/usr/local/bin/stream-watchdog.sh`, was changed on

## Why ACD is off

Something on the campus Wi-Fi sends ARP packets that claim the Pi's own address,
from MAC `00:00:00:00:00:00`. NetworkManager's ACD (RFC 5227) is on by default,
and it takes these packets as a conflict. At a later DHCP renewal it removes the
address and the default route. The Wi-Fi stays associated, but the Pi has no
IPv4 until its lease runs out about 50 minutes later.
[streamingLambda#9](https://github.com/vertical-cloud-lab/streamingLambda/issues/9#issuecomment-5844810174)
found this. The same packets reached the powder-doser Pi within 5 s, so they
come from the network, not from either Pi. Over the 57-day archive, outages
with this pattern add up to about 21 h of missing OT-2 footage, roughly half of
all its downtime.

On 2026-09-25, this Pi's journal shows the whole sequence:

| time (MDT) | event |
| --- | --- |
| 23:00:26, 23:25:39, 23:55:39 | `conflict detected for IP address <its own> with host 00:00:00:00:00:00`. The last two came at DHCP renewals |
| 23:55:41 | address and default route removed; the stream stops |
| 23:59:56 | the watchdog sees no progress in 3 checks and restarts `device.service` |
| 00:00:35 | all three starts have failed on `Temporary failure in name resolution`, and systemd gives up |
| 00:48:09 – 00:49:06 | the lease runs out; NetworkManager reconnects and gets the same address |
| 00:49:40 | the watchdog starts the stream again, as [`HHwgJks2-ec`](https://www.youtube.com/watch?v=HHwgJks2-ec). About 54 min is missing |

`ipv4.dad-timeout=0` in a `[connection]` section makes 0 (off) the default for
every connection profile that doesn't set its own value. The Wi-Fi profile,
`netplan-wlan0-byu-devices`, is generated by netplan and leaves it at `-1` ("use
the default"). So the setting applies to that profile without any change to
netplan. `nmcli -g ipv4.dad-timeout connection show netplan-wlan0-byu-devices`
should keep printing `-1`.

The trade-off: the Pi no longer notices a real duplicate address. The DHCP
server hands out the addresses, so one shouldn't occur.

## It shares `[connection]` with the power-save file

The Pi already had `/etc/NetworkManager/conf.d/wifi-powersave-off.conf` from
#172:

```ini
[connection]
# 2 = disable Wi-Fi power saving (Pi Zero 2 W drops off Wi-Fi with it enabled)
wifi.powersave = 2
```

NetworkManager merges sections with the same name key by key across `conf.d`
files. So the new file adds a key to `[connection]` and doesn't replace
`wifi.powersave`. This was checked before installing, by running
`sudo NetworkManager --print-config --config-dir=<temp dir>` on a copy of
`conf.d` with the new file added. After installing, the merged configuration
reads:

```ini
[connection]
ipv4.dad-timeout=0
wifi.powersave=2
```

## When it takes effect

The file was installed and loaded into the running NetworkManager with
`nmcli general reload conf`. The Wi-Fi connection that was already up wasn't
reconnected, so the stream carried on. The setting applies from the next time
the Wi-Fi connects: here, the 05:00 reboot from the root crontab.

To check after a boot, run
`journalctl -b -u NetworkManager | grep "acd pending"`. It should print
nothing. Before the change, every connection logged
`new lease, address=…, acd pending`.

## Installing it again, or undoing it

From this directory, with sudo's password fed on stdin as `CLAUDE.md` describes:

```sh
ssh "$OT2_STREAM_CAM_USERNAME@$OT2_STREAM_CAM_HOSTNAME" 'cat > /tmp/no-ipv4-acd.conf' < no-ipv4-acd.conf
ssh "$OT2_STREAM_CAM_USERNAME@$OT2_STREAM_CAM_HOSTNAME" \
  "sudo -S -p '' sh -c 'install -m 644 /tmp/no-ipv4-acd.conf /etc/NetworkManager/conf.d/ && nmcli general reload conf && rm /tmp/no-ipv4-acd.conf'" \
  <<< "$OT2_STREAM_CAM_PASSWORD"
```

To undo, run `sudo rm /etc/NetworkManager/conf.d/no-ipv4-acd.conf` and then
`sudo nmcli general reload conf`. As with the install, it takes effect the next
time the Wi-Fi connects.

The powder-doser Pi got the same file on 2026-09-26 at 03:07 MDT, in
streamingLambda#9.
